# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Silent drift | Compare the plan's stated scope, intended behavior, and boundaries with the branch diff. Read any `## Deviations` section and compare the draft PR title and description with the actual diff. In eval mode, use the plan-context, candidate diff, deviation notes, and description in the bundle. | Every substantive change and omission is consistent with the plan, or a deviation is explicitly documented with a reason. The PR description accurately represents what the diff does and does not deliver. An honestly documented, justified shortfall can pass; an unexplained mismatch or a misleading description fails. | required |
| Not tested | Compare test_evidence.md to the plan test plan/repro; before/after outcomes and control results; eval test evidence and plan context. | Evidence demonstrates the main planned behavior change and records relevant test outcomes. Concrete command output is strongest, but a clear, specific test summary can establish an outcome without reproducing every line of output. Consider the package's evidence as a whole: a demonstrated primary repro, a reported passing relevant test suite, and a specific summary of control results may be sufficient. Do not require every control's full transcript when its result is explicitly reported and there is no contradictory evidence. If a check could not run or a test is incomplete, the limitation/reason must be disclosed and success must not be claimed. A bare "tests pass" with no relevant test details fails. | required |
| Unreviewable | Inspect the complete branch diff and changed-file list against the plan's boundary. Look for debug output, dead code, commented-out experiments, unrelated edits, accidental generated files, and formatting churn that obscures the fix. In eval mode, use the candidate diff and commit information in the bundle. | The intended change is identifiable and reviewable, and unrelated changes or leftover debris do not obscure it. Every substantive change belongs to the planned work or a documented deviation. A focused diff can pass even if it is not minimal; unrelated or unexplained changes that make review materially harder fail. | required |
| Standards wall | Compare the draft PR description with the repository's PR template, `docs/CONTRIBUTING.md`, and any applicable maintainer instructions in the issue thread. In eval mode, use the repo-facts block's template asks and stated policies and the candidate description. Check required sections, issue references, testing claims, reviewer notes, and applicable AI-use disclosure. | The description addresses every applicable required template section with relevant, truthful content, follows the stated repository instructions, and includes any required disclosure. A section may explain honestly that something was not applicable or could not be completed, rather than making an unsupported claim. An omitted required section, missing required disclosure, or ignored explicit instruction fails. | required |

## Verdict rule

Accept if every required check passes. Reject if any required check fails. Treat `unclear` as a failure for required checks unless the available evidence resolves the uncertainty. Preferred checks, if added later, do not change the verdict.

Do not require a PR to claim perfection. An honestly documented limitation or justified deviation can pass when the evidence is sufficient, the remaining work is represented accurately, and all applicable repository requirements are met. Do not accept an unsupported claim merely because it is phrased confidently or accompanied by a disclosure.
